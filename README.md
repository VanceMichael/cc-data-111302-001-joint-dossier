# 企业迁移联办门户的共用材料采集与分支续办

这是用于内部数据接入的 Node.js 项目。浏览器页面和仪器网关使用合成业务资料，不连接真实账户、设备或个人资料。项目在原有本地来源之上增加了**窗口工作台**与**浏览器自动化助手**：助手先回读门户页面实际要求，再按部门形成可核对的材料使用记录与真实回执；它不代替工作人员作审批决定。

## 环境与命令

Node.js 22.20.0 或更新的 22.x。依赖由 package-lock.json 锁定。

```sh
npm ci --ignore-scripts
npm run build
npm test
npm start
```

`npm start` 会同时启动本地来源与工作台，并在标准输出分别报告地址：

```json
{"source":"http://127.0.0.1:PORT","status":"来源服务就绪"}
{"workbench":"http://127.0.0.1:PORT","status":"工作台就绪"}
```

默认绑定本机回环地址并使用动态端口。可用环境变量控制：

| 变量 | 含义 |
| --- | --- |
| `HOST` | 绑定地址，默认 `127.0.0.1` |
| `PORT` | 来源端口；未设置时使用动态端口 |
| `WORKBENCH_PORT` | 工作台端口；未设置时使用动态端口 |
| `STATE_DIR` | 事项状态目录，默认 `.local` |
| `CASE_ID` | 事项号，默认 `move-17` |
| `SOURCE_URL` | 复用已在运行的同来源，而不是新建 |
| `HEADLESS` | 设为 `0` 时显示浏览器窗口 |

`npm run demo` 在同一进程启动来源，读取一次目录后退出，不代表持续接收业务已经完成。`npm run walkthrough` 用真实浏览器点击与回读，演示“迁入地址修订、医保授权撤回、公积金补件”交错发生时的窗口工作台输出。

```sh
docker build -t joint-dossier:local .
docker run --rm --network none joint-dossier:local
```

依赖在镜像构建阶段安装，运行阶段不需要公网。浏览器在无界面模式执行，页面交互不依赖人工鼠标。宿主机首次运行浏览器测试前执行 `npx playwright install --with-deps chromium`。

## 助手的工作方式

1. **先回读，后动作。** 每个操作都先在真实门户页面上读取企业资料版本、部门授权版本，以及每个部门页签实际渲染的字段与文件要求。未回读前工作台显示“未回读”，不会给出办结或可续办结论。
2. **共用字段只认门户版本。** 企业名称、迁入地址属于共用资料，即使有人在部门页输入框里手改，也以门户修订后的 `profile.version` 为准；页面上无法归属版本的输入值不会被当成企业资料。
3. **已受理即冻结。** 部门受理回执冻结当时的字段与版本。此后共用字段修订，已受理分支的状态变为“已受理（冻结旧版）”，只产生一条“待登记更正”，再次点击续办只会返回 `correction-only`，绝不重送新版。
4. **未送出的分支取新值。** 尚未受理的分支在回读后按当前企业资料版本组装材料，因此修订后送出的是新地址。
5. **补件按部门隔离。** 某部门要求补件时，仅该部门进入待补；其余分支照常推进。总事项保持“待补件/未办结”，不会因为其他分支受理而误报办结。文件类要求（如公积金 `paymentProof`）以资料引用登记，并记入该部门专用材料版本。
6. **授权撤回只作用于该部门。** 撤回后不再向该部门送出任何新材料，回读会将其标为“授权已撤回，禁止分发”；其他部门已合法受理的回执原样保留，总事项仍为未办结。
7. **结果不明先核对。** 分发响应中断或无法解析时，助手把分发记为“待核对”，下次回读先按内容向来源核对回执：已形成回执则直接采信，不再重送。
8. **同一事项串行化。** 状态写入事项文件，并通过事项级文件锁串行化；两个工作台同时操作同一分支只会有一个真实回执。重启服务后继续读取同一事项文件。

## 工作台

打开启动日志中的 `workbench` 地址即可。页面按部门展示：

- 状态与真实回执（回执号、受理状态、资料版本、授权版本）；
- 待补材料（含字段/文件类型）；
- 授权依据与当前授权版本；
- 每份材料使用的版本与冻结标记；
- 材料使用记录：共用材料按版本记录被哪些部门使用，部门专用材料只归属该部门。

## 目录

- `src/source.mjs`：本地来源生命周期与 HTTP 入口（门户页面、部门接收、回执与控制）。
- `src/assist.mjs`：助手状态机，负责回读、材料计划、分发、补件、更正与总事项判定。
- `src/portal.mjs`：在真实门户 DOM 上回读要求、填写与分发。
- `src/journal.mjs`：事项文件与跨进程文件锁。
- `src/app.mjs`：工作台 HTTP 接口与页面入口。
- `src/serve.mjs`：一个命令启动来源与工作台。
- `public/index.html`：联办门户（三个部门页签、资料修订、授权撤回）。
- `public/workbench.html`：窗口工作台。
- `fixtures/source.json`：来源初始状态。
- `docs/source-contract.md`：来源协议范围、控制与领域语义。
- `test/source.test.mjs`：来源与门户集成测试。
- `test/assist.test.mjs`：回归用例，覆盖分支隔离、并发、重启、授权撤回、旧版冻结与结果不明分发。
- `scripts/walkthrough.mjs`：真实点击与回读的交错场景演示。

运行时来源状态仅用于模拟，重启来源会回到 fixtures 中的值；业务状态请保留在 `.local/` 或明确的外部路径。来源管理入口 `/state`、`/control` 与 `/receipts` 是本地操作与核对设施，不是绕过门户页面的业务写入捷径。
